### 5. `references/常見錯誤.md` — 併入這幾列

繪本／分層動畫專屬的症狀，`繪本插畫動畫.md` 末尾有完整表，這裡挑跨風格通用的四則：

| 症狀 | 原因 | 修法 |
|---|---|---|
| 分段渲染的接縫處畫面跳掉 | 場景生成用了 `Math.random()`，每次重載都不一樣 | 換固定種子 PRNG（`mulberry32`）；`seek(t)` 必須是純函式 |
| 畫面出現不該有的水平硬線 | 霧／漸層區塊用了純色 `<rect>` | 換 `linearGradient` 往下淡出 |
| 瀏覽器起不來、叫你跑 `playwright install`（跑了也沒用） | pip 版 playwright 與系統 chromium 版號不合 | `launch(executable_path="<chromium 路徑>")` |
| 合成後聲音很小，推大就爆 | 只看 LUFS 沒看真實峰值餘裕 | 先量 json；餘裕不夠就走兩段式 loudnorm（見下） |

### 6. `references/剪輯工藝.md` — 音訊段落補「兩段式 loudnorm」

現有做法（平推增益）在 LRA 小的時候沒問題，但**峰值餘裕不夠時會爆**。補這段判斷：

```
量：ffmpeg -i in.mp4 -af loudnorm=I=-14:TP=-1.5:LRA=11:print_format=json -f null -

目標增益 = -14 − input_i
若 input_tp + 目標增益 < -1.5  → 平推 volume=XdB（最乾淨，不動動態）
否則                          → 兩段式：把 measured_I / measured_TP / measured_LRA /
                                measured_thresh / offset 五個值餵回第二段
```

順便補編碼那段：**平塗／插畫類畫面 crf 用 23 就好**，crf 18 只是在編碼顆粒雜訊，
並排放大比對看不出差別，檔案卻是兩倍大。

## 三、水彩插畫：這次沒有動到，但有兩個缺口

**這包沒有修改 `references/插播動畫.md`。** 水彩插畫原本的內容一個字都沒改，
只是 `SKILL.md` 的風格清單從五種變六種、Step 5 多一句指向新文件。

兩種很容易搞混，選錯就白做，所以把差別寫清楚：

| | 水彩插畫 | 繪本插畫（新） |
|---|---|---|
| 素材 | AI 生圖 ×2（9:16 背景 + 純白底角色，PIL 去背） | 沒有素材，整個場景 SVG 畫出來 |
| 動態 | 背景 Ken Burns + 角色 sin 搖擺 + 光點 | 每層獨立運鏡，深度視差 |
| 依賴 | 要生圖服務或瀏覽器帳號 | 完全不依賴外部服務 |
| 質感 | 真水彩筆觸，AI 畫得出來的細節 | 平塗色塊，寫實做不出來 |
| 適合 | 單場景、氣氛、一句話一個畫面 | 多鏡頭、有空間移動的故事片 |
| 換場景的成本 | 再生一張圖（快） | 再畫一組 SVG（慢） |

**選法**：使用者要的是「一張漂亮的畫在呼吸」→ 水彩。
要的是「鏡頭穿過空間、走進去又走出來」→ 繪本分層。

### 缺口 1：範例跑不起來

`examples/範例_水彩疊層動畫.html` 需要兩張外部素材才會有畫面：

```
wc_bg.png      9:16 水彩場景背景（上 2/3 留白給文字、無文字無角色）
wc_bunny.png   角色全身圖（純白底，用 PIL 轉透明去背）
```

繪本那兩支範例是自足的（只要 `grain.png`），水彩這支不是。
補上一組實際用過的素材，它才算一份「可以照抄」的工藝範例。

### 缺口 2：沒有 worked example

`剪輯工藝.md` 有 worked example，水彩沒有。
**「AI Bunny 也要賺錢的一天」那支正好可以補這個洞**——它是真的做完、真的發出去的，
比通用模板有價值得多。要補的話需要那支的專案資料夾：

```
03_圖/         wc_bg.png、wc_bunny.png（或當時實際的檔名）
生圖 prompt    當初餵給 ChatGPT / Gemini 的那段（最有價值的其實是這個）
那支 HTML      改過的 seek(t)、字卡文案、時間軸
07_成品/       final.mp4（有的話）
```

**最少給我 HTML + 兩張素材 + 生圖 prompt** 就能寫成範例。
成品 mp4 不是必要的，而且大檔傳輸有限制。

## 四、順手記一筆：token 成本

這次全程 5,800 萬 tokens，其中 94% 是快取讀取（每輪重讀整段對話）。
真正的輸出只有 37.5 萬。**渲染完全不花 token**——1440 格截圖、ffmpeg、
配樂合成全是 CPU。

最花 token 的是「看圖改稿」：每張讀進來的截圖，之後每一輪都要重讀一次。
所以 `繪本插畫動畫.md` 裡把**接觸表**列為 QC 的標準做法，
一顆一顆單獨截圖看是最貴的做法。
