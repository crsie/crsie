# 繪本插畫動畫（SVG 分層）

> 第六種插播動畫。和「水彩插畫」的差別：水彩是 **AI 生圖 + HTML 疊層**（一張背景圖做 Ken Burns、
> 一張去背角色搖擺）；這條是 **整個場景用 SVG 平塗畫出來**，每一層都能獨立動。
> 引擎共用 `scripts/html_render.py`（寫 HTML 定義 `seek(t)` 逐格算圖）。

## 什麼時候走這條

| 情況 | 走哪個 |
|---|---|
| 使用者拿參考圖說「我要這種繪本感／插畫感」 | ★ 這條 |
| 要做**多鏡頭、有故事**的片（不只是動態字卡） | ★ 這條 |
| 手上沒有生圖服務、也不想開瀏覽器去生 | ★ 這條（完全不依賴外部服務） |
| 使用者已經有一張很滿意的插畫，只想讓它動 | 水彩插畫（`插播動畫.md`） |
| 要真實質感、寫實光影 | 生圖／生片，不要用這條 |

**這條最大的優勢是視差。** 單張生成圖只能整張一起縮放，看起來永遠是「一張圖在放大」；
分層之後天空、遠景、中景、近景、角色可以用不同倍率推進，畫面才會有空間。
使用者說「怎麼做出好看的動畫」的時候，他要的多半就是這個。

**代價是你要自己畫。** 平塗的樸素派／繪本風剛好是 SVG 畫得動的（大色塊、無透視、無漸層），
寫實風格不要嘗試。

---

## 鐵則一：`seek(t)` 必須是純函式

**分段渲染 = 頁面重新載入好幾次。** 場景生成如果用 `Math.random()`，
每個 chunk 的樹叢位置都不一樣，接縫處會整片跳掉。

固定種子，貼這段：

```js
function mulberry32(a){return function(){a|=0;a=a+0x6D2B79F5|0;var t=Math.imul(a^a>>>15,1|a);
  t=t+Math.imul(t^t>>>7,61|t)^t;return((t^t>>>14)>>>0)/4294967296}}
var rnd=mulberry32(20260809);          // 換這個數字＝換一個世界
function R(a,b){return a+(b-a)*rnd()}
```

同理**不要**用 CSS animation、`setInterval`、或任何累加狀態。所有位置一律由 `t` 算出來。

## 鐵則二：美術規格先定死，再開始畫

一支片只用一組色票，寫在檔頭。不確定就少用顏色。

| 元素 | 做法 |
|---|---|
| 上色 | 純平塗，**不要漸層**（天空與光暈例外） |
| 陰影／受光 | 用**橢圓**疊在形狀的 clipPath 內，不要用偏移的同形狀 |
| 色調 | 低彩度大地色。綠 `#2A4A2C`→`#8AAF66`、黑大衣 `#14161B`、膚 `#E8B79E`、髮 `#C25A3A` |
| 紙紋 | 兩層顆粒：`overlay` 20% 提亮 + `multiply` 10% 壓暗（同一張 noise PNG，第二層放大 150px） |
| 收尾 | 米色紙調 `multiply` 10% + 暖光 `soft-light` + 暗角 26% |

顆粒圖用 Pillow 產一次就好：

```python
from PIL import Image; import random
random.seed(7); S=300
img=Image.new('RGBA',(S,S)); px=img.load()
for y in range(S):
    for x in range(S): v=random.randint(0,255); px[x,y]=(v,v,v,255)
img.save('grain.png')
```

**最後那三層（顆粒／暖光／暗角）是把畫面「黏成同一張紙」的關鍵。**
沒有它們，各個色塊看起來就是各自獨立的向量圖形。

## 鐵則三：分層與視差

每層給一個「深度值」，鏡頭推進時各層套不同倍率：

```js
function cam(fx,fy,k,dx,dy){
  return "translate("+(fx*(1-k)+(dx||0))+","+(fy*(1-k)+(dy||0))+") scale("+k+")";
}
var k = 1 + (s-1) * depth;      // s = 鏡頭當下的縮放
```

實測好用的一組深度（由遠到近）：

| 層 | depth |
|---|---|
| 天空 | 0.15 |
| 雲 | 0.20 |
| 鳥 | 0.24 |
| 遠丘 | 0.38 |
| 後排樹 | 0.52 |
| 中排樹 | 0.72 |
| 中景地面 | 0.86 |
| 前排樹 | 1.00 |
| 前景草地 | 1.14 |
| 角色 | 1.22 |
| 最前景草葉 | 1.55 |

**空氣遠近感**：遠處疊一層淡色往下淡出的 `linearGradient`。
★ **一定要用漸層，不能用純色 `<rect>`**——純色矩形會在畫面中間切出一條硬線，
而且這條線在慢推的時候會跟著動，非常明顯。

## 鐵則四：只動一點點

一支 60 秒的片，全部的動作可以只有這些：風吹樹叢、草擺、雲飄、鳥飛過、
衣角輕晃、動物抽耳朵（＋一次小跳）、浮塵。**沒有走路、沒有轉身、沒有揮手。**

克制不只是美感問題——平塗角色一做大動作就會露餡（沒有骨架、沒有透視）。

風用**兩個不同頻率的 sin 相加**，避免規律得像節拍器：

```js
function wind(t,a,b){return Math.sin(t*0.55+a)*b + Math.sin(t*1.02+a*2.3)*b*0.46}
```

抽動類的動作用「時間點陣列 + 衰減脈衝」，不要用週期函數（會變成機械式抽搐）：

```js
function earTwitch(t,times){
  var v=0;
  for(var i=0;i<times.length;i++){var d=t-times[i];
    if(d>0&&d<0.55) v=Math.max(v,Math.sin(d/0.55*Math.PI)*Math.abs(Math.sin(d*26)));}
  return v;
}
```

## 鐵則五：場景切換要疊在不透明的舊景上

★ 這條在 `常見錯誤.md` 已經有一則（轉場鬼影），分層動畫更容易踩到。

**每個場景第一個元素必須是滿版不透明底。** 切換時新場景 `opacity 0→1` 疊在舊場景上面，
舊場景維持 opacity 1 直到完全被蓋住才隱藏。兩層都半透明的交叉淡化會看到穿幫。

```js
for(var i=0;i<N;i++){
  var t0=i*SEG, t1=t0+SEG;
  var vis=(t>=t0-0.65 && t<t1+0.2);           // 只留兩層在 DOM 裡
  g.setAttribute("display", vis?"inline":"none");
  if(vis) g.setAttribute("opacity", i===0 ? 1
        : clamp(ease((t-(t0-0.55))/0.6),0,1));  // 淡入在 t0 完成
}
```

需要「穿過去／突然開闊」的轉場，用**亮閃**取代溶接：一個滿版暖白 div，
在切點前後 0.45 秒內做三角波 opacity（峰值 0.6 左右）。

## 多鏡頭故事片的結構

使用者說「要一個完整的故事」時，用 **12 顆 × 5 秒 = 60 秒**。這個規格很好用：
5 秒剛好夠讀完兩行字卡，12 顆夠走完一條完整的弧線，而且 1440 格渲染得完。

弧線照這個骨架排，每一顆對應一個階段：

```
困住(1-3) → 契機(4-5) → 猶豫/決定(6) → 穿越(7) → 開闊(8-9) → 高點(10-11) → 收(12)
```

**分鏡表要先給使用者看過再開工。** 這不是客套——12 顆鏡頭是 1440 格，
渲染 9～26 分鐘，故事不對整支重來。提案時講內容（每顆的畫面＋字卡），
不要貼場景 id 叫他自己想像。

字卡一顆一張，進 0.7s、出 0.6s。上緣**不要高於畫面 15%**（IG 頂部那條會蓋到）；
座標一律以 `版型與安全區.md` 為準。

## 產線

### 環境

除了 `check_env.py` 那些，這條額外要注意兩件事：

**1. pip 版 playwright 對不上系統 chromium 版號**，會噴「playwright install」但裝了也沒用。
用 `executable_path` 直接指：

```python
b = await p.chromium.launch(executable_path="/opt/pw-browsers/chromium",
        args=["--no-sandbox","--disable-gpu","--disable-dev-shm-usage"])
```
（路徑因機器而異，先 `ls` 找到實際的 chromium 執行檔。）

**2. 有些環境的 ffmpeg 只有 VP8 沒有 libx264**（例如 playwright 自帶的那支）。
`ffmpeg -encoders | grep libx264` 確認，沒有就裝系統版。

### 平行渲染（★ 這條要記起來）

`render_chunk.py` 是照 frame index 寫檔的，所以**同一份 HTML 可以開多個 process
各跑一段互不干擾**。核心數 -1 個 worker 是安全值：

```bash
# 4 核，1440 格 → 三個 worker，26 分鐘壓到 9 分鐘
python3 render_chunk.py reel.html /tmp/frames 540 960 2    0  480 &
python3 render_chunk.py reel.html /tmp/frames 540 960 2  480  960 &
python3 render_chunk.py reel.html /tmp/frames 540 960 2  960 1440 &
wait
```

★ **不要用 `pkill -f render_chunk.py` 去停**——你自己的 shell 指令列裡也有這個字串，
會把自己殺掉。用 pid 或工作管理。

### QC：用接觸表，不要一顆一顆看

抽每顆鏡頭中間那格，**拼成一張接觸表再看**。
一顆一顆截圖讀進來，每張圖之後每一輪都要重讀一次，token 會爆掉；
六宮格一張圖看完六顆鏡頭，成本差一個量級。

```bash
python3 contact.py reel.html 2.5,7.5,12.5,17.5,22.5,27.5,32.5,37.5,42.5,47.5,52.5,57.5 contact.png
```

看接觸表要找的是這些（都是實際踩過的）：形狀有沒有長出奇怪的邊、
有沒有元素浮在半空、有沒有橫向硬線、有沒有哪一顆空到沒東西看。

### 合成與響度

★ **平推增益只在 LRA 小的時候能用。** 先量：

```bash
ffmpeg -i raw.mp4 -af loudnorm=I=-14:TP=-1.5:LRA=11:print_format=json -f null -
```

- 「目標增益」＝ -14 − input_i。如果 `input_tp + 目標增益 < -1.5`，直接 `volume=XdB` 平推最乾淨（不動動態）。
- 峰值餘裕不夠（會爆）就走**兩段式**：把量到的五個值餵回第二段，讓 loudnorm 自己做增益＋真實峰值限制。

```bash
ffmpeg -i raw.mp4 -af "loudnorm=I=-14:TP=-1.5:LRA=11:\
measured_I=-25.08:measured_TP=-9.58:measured_LRA=3.70:measured_thresh=-35.18:\
offset=-0.74:linear=true" -ar 48000 -ac 2 -c:v copy -c:a aac -b:a 192k out.mp4
```

實例：60 秒那支量到 -25.1 LUFS、真實峰值 -9.6 dBTP。要到 -14 得推 11.1dB，
但只有 9.6dB 餘裕 → 平推會爆到 +1.5 dBTP，只能走兩段式。

### 編碼：crf 18 是浪費

平塗畫面沒有高頻細節，顆粒又是自己疊上去的，**crf 給太高只是在編碼雜訊**。
`crf 23 preset slow` 和 crf 18 並排放大比對看不出差別，檔案從 44 MiB 掉到 26 MiB。
交付／傳輸有大小限制時直接用 23。

## 常見錯誤

| 症狀 | 原因 | 修法 |
|---|---|---|
| 分段渲染的接縫處畫面跳掉 | 場景用了 `Math.random()` | 換固定種子 `mulberry32` |
| 樹／灌木頂端長出鉤狀怪邊 | 受光面用「偏移的同形狀」，頂端曲線互切 | 陰影受光改用**橢圓**，clip 在形狀內 |
| 畫面出現水平硬線 | 空氣霧用了純色 `<rect>` | 換 `linearGradient` 往下淡出 |
| 前景元素浮在背景上面 | 元素的 y 範圍蓋到了不該去的區間 | 草地類元素限制在地平線以下 |
| 樹叢像聖誕樹 | 圓錐控制點太靠內、高寬比太大 | 控制點拉到 0.78w，高寬比降到約 3.7 |
| 光源被物件蓋掉 | 光先畫、遮擋物後畫 | **牆先畫，光疊最上層**（光暈→亮核→光帶→地面光池） |
| 手／肢體散成好幾根香腸 | 手指用獨立方塊拼 | 掌心一塊 + 手指用**同色圓角筆畫**疊上去，會自然融合 |
| 「捧著光」看起來像在打招呼 | 光球在指尖上方、手指張太開 | 光球放進掌心（低於指尖）、手指收攏、整隻手轉 10–16° |
| 近景人物變成一根黑柱 | 沒有肩線 | 加肩線＋兩道衣褶＋髮絲（遠景時自然看不見，不用做兩套） |
| 海面反光像雜訊 | 隨機小點 | 改成從光源正下方往觀眾**逐階變寬**的光帶，再加微量抖動 |
| 淺色天空上的字看不清，壓黑後天空變髒 | 亮背景不該壓黑 | 改**深色字 + 淡色外光**，不要壓黑 |
| 瀏覽器起不來、叫你 playwright install | pip 版與系統 chromium 版號不合 | `launch(executable_path=...)` |

## 交付

照 `剪輯工藝.md` §⑩，三件套不變：`final.mp4` + `final.srt` + `封面.jpg`。

字幕由字卡直接轉 SRT（時間軸就是 `SEG` 陣列，不用再對一次）。
封面抽一格乾淨畫面（**把字卡、壓黑層、浮水印關掉**再截），標題用 Pillow 疊，
位置照樣避開臉／主體。
